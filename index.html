01 / Definições

Os 5 níveis, do código ao agente autônomo

"Agente" virou nome para tudo. Na prática existe uma escada. Cada degrau entrega mais flexibilidade e cobra mais custo, latência e risco. Toque em um nível para abrir.

0

Regra determinística

Código puro. A mesma entrada sempre gera a mesma saída. Sem modelo.
Use quando
A regra cabe em um if, uma fórmula ou uma consulta.
No kit
Dígito verificador de CNPJ, documento vencido, kit completo.
Para o PM
Custo quase zero e 100% auditável. Sempre a primeira opção.
Para a engenharia
Funções puras, testes unitários, motor de regras versionado.
1

Chamada única de LLM

Um prompt, uma resposta estruturada. O modelo faz uma tarefa só.
Use quando
A entrada é bagunçada (texto livre, imagem, PDF) e a tarefa é única: classificar, extrair, resumir.
No kit
Reconhecer que o PDF é um contrato social e extrair os sócios.
Para o PM
Barato e rápido. Um modelo pequeno costuma resolver.
Para a engenharia
Saída em JSON com schema, temperatura baixa, confiança por campo.
2

Workflow

Várias chamadas de LLM e de código em um caminho que você desenhou. Padrões comuns: encadeamento, roteamento, paralelização, gerador com revisor.
Use quando
Você conhece os passos de antemão e eles se repetem.
No kit
Classificar → extrair → validar → cruzar com a Receita.
Para o PM
Previsível. Dá para estimar custo, prazo e taxa de acerto por etapa.
Para a engenharia
Grafo ou máquina de estados, retries, cada etapa testável isolada.
3

Agente com ferramentas

O modelo decide qual ferramenta chamar e em que ordem, em loop, até atingir o objetivo. Escopo e limites definidos por você.
Use quando
O caminho muda caso a caso e não dá para desenhar todos os ramos.
No kit
Investigar divergência entre contrato social e quadro societário. Abrir a cadeia de sócios PJ até o beneficiário final.
Para o PM
Resolve as exceções que hoje caem no analista. Custo e tempo variam por caso.
Para a engenharia
Lista fechada de tools, limite de passos e de custo, log de cada decisão.
4

Agente autônomo e multiagente

Planeja, executa tarefas longas e coordena outros agentes com pouca supervisão.
Use quando
O problema é aberto, o valor é alto e o erro é reversível.
No kit
Pesquisar mídia negativa e montar o dossiê para o analista de PLD.
Para o PM
Maior potencial e maior risco. Comece com um humano aprovando o resultado.
Para a engenharia
Sandbox, permissão mínima, checkpoints, avaliação contínua.
Regra de ouro: suba um nível só quando o nível de baixo não resolve.
02 / Comparação

Workflow x agente autônomo

A diferença central é quem decide o próximo passo: você ou o modelo.

Workflow

O caminho é seu

  • Quem decide os passosO código. O LLM atua dentro de cada etapa.
  • PrevisibilidadeAlta. Mesmo fluxo toda vez.
  • Custo e latênciaFixos e estimáveis.
  • TesteEtapa por etapa, com casos conhecidos.
  • AuditoriaSimples. Cada etapa tem entrada e saída registradas.
  • Melhor paraProcesso repetitivo, regulado e de alto volume.
Agente autônomo

O caminho é do modelo

  • Quem decide os passosO modelo, a cada volta do loop.
  • PrevisibilidadeMenor. Dois casos iguais podem seguir rotas diferentes.
  • Custo e latênciaVariáveis. Precisa de teto.
  • TestePor resultado final e por trajetória, em um conjunto de casos de referência.
  • AuditoriaExige log completo de raciocínio e chamadas.
  • Melhor paraExceções, investigação e tarefas abertas.

Na vida real os dois convivem: um workflow cuida do fluxo principal e chama um agente só nos pontos em que o caminho é imprevisível.

03 / Decisão

Quando criar um agente

Agente é a resposta para imprevisibilidade. Se o processo é previsível, ele só adiciona custo e risco.

Teste rápido: seu caso pede um agente?

    Responda as 5 perguntas para ver a recomendação.

    Crie quando

    • O número e a ordem dos passos mudam de caso para caso.
    • Desenhar todos os ramos em um fluxograma ficou inviável.
    • O valor de resolver o caso paga o custo e a espera.
    • O erro é detectável e reversível antes de causar dano.
    • Existe um jeito claro de medir se o resultado está certo.

    Não crie quando

    • Uma regra, uma consulta ou uma fórmula resolve.
    • Os passos são sempre os mesmos. Isso é um workflow.
    • A resposta precisa ser idêntica toda vez.
    • O erro é irreversível ou tem impacto regulatório direto.
    • Ninguém consegue dizer como avaliar a saída.
    04 / Validação

    Onde tem que ser determinístico

    O LLM lê e interpreta. O código decide.

    Determinístico

    Sempre em código

    • Cálculo e aritmética.
    • Formato e dígito verificador (CPF, CNPJ).
    • Datas, prazos e validade.
    • Dado oficial: vem da consulta à fonte, nunca da memória do modelo.
    • Comparação com listas restritivas, com algoritmo de similaridade e limiar definido.
    • Regras de política e de alçada.
    • Decisão final de aprovar ou reprovar.
    • Trilha de auditoria.
    Probabilístico

    Onde o LLM entra bem

    • Ler documento escaneado, foto torta, PDF sem padrão.
    • Classificar o tipo de documento.
    • Extrair campos para um formato estruturado.
    • Normalizar nomes, endereços e razões sociais.
    • Interpretar cláusulas: quem assina, com quais poderes.
    • Resumir o caso para o analista.
    • Explicar a pendência para o cliente em linguagem simples.

    O padrão que funciona: o LLM transforma o documento em dados, o código valida os dados contra regras e fontes oficiais, e só o que sobra de dúvida vai para um agente ou para uma pessoa.

    05 / Caso prático

    Kit de documentação no CRM

    Cenário: a empresa tem um CRM e um portal onde o cliente envia o kit de documentos para ser aprovado. Hoje um analista abre arquivo por arquivo. O objetivo é tirar o fator humano de quase toda a validação.

    1. Recebimento e completudeO kit tem todos os documentos exigidos para aquele tipo de cliente?
      Regra
    2. Conferência de tipo e qualidadeO arquivo é mesmo o documento pedido naquele campo do portal? Está legível?
      Mini LLM
    3. ExtraçãoOCR e modelo pequeno transformam cada documento em campos estruturados com nível de confiança.
      OCR + mini LLM
    4. Validações de regraDígitos, datas, campos obrigatórios, coerência entre documentos.
      Regra
    5. Fontes oficiaisSituação cadastral, segmento (CNAE) e quadro societário consultados na Receita e comparados com a política.
      API + regra
    6. Sócios e prevenção à lavagem de dinheiroSócios do contrato x quadro societário, listas de sanções, pessoas expostas politicamente, mídia negativa, beneficiário final.
      RegraAgenteHumano
    7. Decisão e roteamentoAprovação automática, pendência devolvida ao cliente ou fila de revisão humana com o dossiê pronto.
      Regra

    Quem valida o quê

    OCR + mini LLM resolve

    Documentos padronizados

    Documento de identidade, cartão CNPJ, comprovante de endereço, certidões. Layout conhecido, poucos campos, alto volume. É onde o fator humano sai primeiro.

    LLM maior + cruzamento

    Documentos semiestruturados

    Contrato social e alterações, procuração, balanço. Texto longo, formato livre. A extração precisa ser conferida contra a Receita e contra os outros documentos do kit.

    Agente + humano

    Casos de julgamento

    Estrutura societária em camadas, notícia envolvendo um sócio, divergência sem explicação. O agente investiga e monta o dossiê. A pessoa decide.

    Quase tudo, não tudo. Dá para automatizar a grande maioria das validações. Casos de baixa confiança, alto risco de lavagem de dinheiro e divergências não resolvidas continuam com uma pessoa responsável, e uma amostra dos aprovados automaticamente deve ser revisada. Valide o desenho final com compliance e jurídico.
    06 / Dúvida de campo

    O portal já sabe o tipo de cada documento. Ainda preciso de agente?

    Cenário comum em onboarding de cliente PJ, que o mercado chama de KYB: o portal tem um campo de upload para cada documento. Contrato social em um, procuração em outro, demonstrações financeiras em outro. A meta é tirar a conferência manual.

    O portal já desenhou o caminho. Isso é workflow, não agente.

    O desenho que resolve

    1. Conferir o campoUma chamada de modelo confirma que o arquivo é mesmo o documento pedido naquele campo.
      Mini LLM
    2. LerOCR e modelo pequeno transformam o documento em campos, em um formato fixo por tipo de documento, com nota de confiança por campo.
      OCR + mini LLM
    3. Validar e cruzarO CNPJ é o da empresa em cadastro? O documento está vencido? Quem assina a procuração aparece como administrador no contrato social?
      Regra
    4. EncaminharAprovado, pendência devolvida ao cliente com o motivo, ou fila de exceção para uma pessoa.
      RegraHumano na exceção

    Onde mora o risco

    Tipo errado

    Documento no campo errado

    O cliente sobe o contrato social no campo da procuração. Por isso o primeiro passo confere o tipo antes de extrair qualquer dado.

    Interpretação

    Leitura que pede julgamento

    Poderes da procuração, assinatura em conjunto ou isolada, contrato social com várias alterações. O modelo lê, mas erra mais aqui. Use modelo maior e revisão humana por amostragem.

    Qualidade

    Arquivo ruim

    Foto torta, carimbo sobre o texto, página faltando. Um limiar de legibilidade devolve o arquivo ao cliente antes de gastar leitura com ele.

    Cadeia

    Cruzamento entre documentos

    A regra é fixa, mas depende de duas leituras corretas. Confiança baixa em qualquer uma delas manda o caso para revisão.

    Nenhum desses riscos pede um agente. Pedem nota de confiança e fila de exceção.
    Workflow

    Continua sendo workflow

    • Validar documento por documento.
    • Barrar documento vencido ou de outra empresa.
    • Cruzar um documento com outro por uma regra conhecida.
    • Devolver a pendência com o motivo.
    Agente

    Vira caso de agente

    • Investigar a exceção sem roteiro pronto.
    • Escolher quais fontes externas consultar.
    • Decidir qual documento complementar pedir.
    • Conversar com o cliente até resolver a pendência.
    O que prometer. Não prometa zero humano. Prometa o grosso aprovado sem toque e o analista olhando só a exceção, já com o motivo apontado. Antes de ligar a aprovação automática, meça a taxa de acerto em um conjunto de kits com resposta conhecida.
    Na prática. Um schema de extração por tipo de documento, validações cruzadas como funções puras, limiar de confiança por campo e um conjunto de referência rodando a cada mudança de prompt ou de modelo. O agente entra depois, como mais um destino da fila de exceção.
    07 / Para o PM

    Como defender, medir e fasear

    O ganho não é "ter IA". É reduzir tempo de aprovação e custo por kit sem aumentar o risco.

    Métricas que importam

    • Aprovação sem toque humanoPercentual de kits resolvidos de ponta a ponta sem analista.
    • Tempo de aprovaçãoDo envio do kit até a resposta ao cliente.
    • Erro por tipoAprovou o que não devia (grave) x barrou o que podia passar (atrito).
    • Custo por kitModelo, consultas externas e tempo de analista nas exceções.
    • Retrabalho do clienteQuantas vezes o kit volta com pendência.

    Roteiro em 3 fases

    Fase 1: copiloto. A IA classifica e extrai, o analista confere tudo. Você mede a taxa de acerto real.
    Fase 2: automático no baixo risco. Kits com alta confiança e sem alertas são aprovados por regra. O resto segue para a fila.
    Fase 3: agente nas exceções. O agente investiga divergências e entrega o dossiê pronto. O analista só decide.
    07 / Para a engenharia

    Contratos, travas e testes

    O LLM nunca escreve direto no CRM. Ele devolve dados com confiança, e um motor de regras decide o que fazer com eles.

    Checklist de arquitetura

    • Saída estruturadaJSON com schema validado. Resposta fora do schema é erro, não texto para interpretar.
    • Confiança por campoAbaixo do limiar o campo vai para revisão, não para a regra.
    • Regras versionadasPolítica fora do prompt, em código ou motor de regras, com histórico.
    • Conjunto de referênciaKits reais anonimizados com resposta conhecida. Todo prompt ou modelo novo roda contra ele antes de subir.
    • Limites do agenteTools em lista fechada, teto de passos, de custo e de tempo.
    • RastreabilidadeDocumento, versão do prompt, modelo, saída e regra aplicada gravados por decisão.
    • Dados pessoaisMascarar o que não é necessário, controlar retenção e acesso conforme a LGPD.

    O contrato entre LLM e regra

    // saída da extração (LLM)
{
  "tipo": "contrato_social",
  "cnpj": { "valor": "00.000.000/0001-00", "conf": 0.98 },
  "socios": [
    { "nome": "Fulano de Tal", "doc": "000.000.000-00",
      "participacao": 60, "conf": 0.91 }
  ]
}

// decisão (código, sem LLM)
if (!cnpjValido(e.cnpj.valor))   return REPROVA
if (menorConfianca(e) < LIMIAR)  return REVISAO_HUMANA
if (!bateComReceita(e.socios))   return AGENTE_INVESTIGA
if (matchListaRestritiva(e))     return REVISAO_PLD
return APROVA
    08 / Glossário

    Os termos, sem jargão

    Para quem não vive o dia a dia de cadastro e compliance.

    KYB
    Know Your Business. O processo de conhecer e aprovar um cliente pessoa jurídica antes de fazer negócio com ele.
    IDP
    Processamento inteligente de documentos. O nome de mercado para a esteira de OCR, extração e validação.
    Human-in-the-loop
    Uma pessoa revisa ou aprova os casos que a automação não resolve com segurança.
    Evals
    Testes que medem a taxa de acerto da IA em um conjunto de casos com resposta conhecida.
    LLM
    Modelo de linguagem. Lê e escreve texto muito bem, mas pode errar com segurança. Por isso não decide sozinho.
    OCR
    Tecnologia que transforma a imagem de um documento em texto.
    Limiar de confiança
    Nota mínima que uma extração precisa atingir para seguir sem revisão.
    Quadro societário (QSA)
    Lista de sócios e administradores de uma empresa registrada na Receita Federal.
    CNAE
    Código que identifica a atividade econômica da empresa. É o que define o segmento.
    Beneficiário final
    A pessoa física que de fato controla a empresa ou se beneficia dela, mesmo por trás de outras empresas.
    PLD
    Prevenção à lavagem de dinheiro. Controles para identificar clientes e operações suspeitas.
    PEP
    Pessoa exposta politicamente. Quem ocupa ou ocupou cargo público relevante, e pessoas próximas. Pede análise reforçada.
    Lista restritiva
    Relação de pessoas e empresas sob sanção ou restrição, nacional ou internacional.
